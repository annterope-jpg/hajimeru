# 回答と最初の行動の対応仕様

版：0.1
確認日：2026-09-06
対象：Phase 5

## 目的

本人が答えた開始上の困りごとを、最も目立つ「最初の行動」へ対応させる。同じ課題文でも、回答が異なれば提案を変える。これは原因の同定や治療選択ではなく、その場で試して修正できる作業仮説である。

## 選択規則

1. 未回答は採点せず、推測しない。
2. `lowActivation`は課題側の順位から分離し、現在状態の調整として扱う。
3. 課題側6軸は6以上を候補とし、得点順で最大2つ選ぶ。
4. 同点は、課題明確性、嫌悪、キュー、競合行動、報酬距離、時間の曖昧さの既定順で決める。
5. 最初の行動は第1仮説へ対応させ、第2仮説は補助的な計画要素として保持する。
6. 該当する課題側仮説がない場合は、課題分類の既定候補を使う。

## 回答から見える提案への対応

| 課題側の作業仮説 | 最初の行動の狙い | 理由タグ |
|---|---|---|
| 課題が曖昧 | 対象を1つにし、観察可能な動詞へ変える | `make_concrete` |
| 嫌悪が強い | 嫌さを消すことを開始条件にせず、30秒だけ接近する | `accept_discomfort` |
| 結果が遠い | 30秒後に変化が見える対象を1つ選ぶ | `bring_reward_closer` |
| 時間が曖昧 | 次の出来事に開始を結びつける | `externalize_cue` |
| 思い出せない・戻れない | 再開地点になる外部の目印を1つ置く | `externalize_cue` |
| 別の行動から切り替えにくい | 競合している画面・道具を一度手放す | `interrupt_competition` |

提案文は30秒以内の物理的・観察可能な動作を目指す。本人はそのまま使う必要はなく、編集、別候補、時間変更、休息を選べる。

## 現在状態の別枠表示

眠気・ぼんやり・身体の重さと、緊張・不安で固まる反応は、課題側の最大2仮説と競わせない。

- 低覚醒：短い身体起動を候補にする
- freeze／緊張：長く息を吐く等、刺激を上げすぎない準備を候補にする
- 両方：小さな調整を本人が選び、続行だけを正解にしない
- 未回答：状態を推測せず、カードを表示しない

これは状態の原因を判定する機能ではない。休息や時間変更を失敗とせず、強い・持続する眠気や身体症状をアプリだけで扱わない。

## セラピスト伴走時

- 出力を正解として説明せず、「今の感覚に近いか」を本人へ確認する。
- 提案がずれた場合は意欲不足と解釈せず、回答、仮説、動作サイズのどこがずれたかを一緒に見直す。
- 第2仮説が重要そうな場合も、本人の同意なく回答や優先順位を上書きしない。
- 低覚醒・freezeの表示から診断、薬剤、睡眠障害等を推定しない。

## 既知の限界

- 第2仮説は最も目立つ行動へ直接反映されない場合がある。
- 汎用候補は、個別課題の安全性、物理環境、必要な技能を理解しない。
- 状態カードは原因鑑別を行わず、Phase 12で読み違い防止を追加検討する。
- 任意AI候補についても、ローカル規則と同じ臨床・安全境界を維持する必要がある。
