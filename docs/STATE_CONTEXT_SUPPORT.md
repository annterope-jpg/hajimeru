# 状態・睡眠・時間帯の読み違いを減らす仕様

版：v0.1

更新日：2026-09-11

対象：Phase 12

## 1. 目的

「身体や頭が重い」という同じ得点を、一律に低覚醒や意欲不足として扱わない。本人が今の経験に最も近いものを任意で選び、開始、縮小、休息、時間変更、相談目安のどれを先に置くか選べるようにする。

これは睡眠障害、概日リズム位相後退、うつ、認知的離脱症候群、身体疾患、薬剤作用等を識別する機能ではない。原因、診断名、治療効果、服薬効果を推定しない。

## 2. 本人が選べる状態

| 選択 | アプリが扱う観察可能な経験 | 初期表示 |
|---|---|---|
| 眠気 | 起きていること自体がつらい | 休息、時間変更、30秒だけ試す |
| 疲れ・消耗 | 使える力が少ない | 休息、時間変更、一歩の縮小 |
| 頭の霧・ぼんやり | 考える、選ぶ、言葉にすることが難しい | 詳細を閉じ、最初の1動作だけを見る |
| 身体の重さ | 身体を動かすことが特に重い | 小さく試す、休息、時間変更 |
| 不安・緊張で固まる | 緊張しているが動きにくい | 希望時だけ短い鎮静準備、休息、時間変更 |
| いくつか重なる | 1つに分けられない | 原因を決めず、縮小、休息、時間変更 |
| まだ分からない | 種類を言葉にできない | 推測せず、縮小、休息、時間変更 |
| 今は特にない | 状態調整を置かない | 通常の開始プラン |

この回答は課題側6軸の採点、最大2仮説、開始率評価を変更しない。未回答は未回答のままにし、旧`activationSource`から新しい詳細状態を合成しない。

## 3. 表示と選択

- 既存の3問目にある任意質問を置き換え、面接項目を増やさない。
- 状態支援がある場合は、状態カードと30秒の一歩だけを先に表示し、仮説、ロードマップ、詳細調整、時間、AIは任意開示にする。
- 開始ボタンは残すが、休息、時間変更、相談目安を同じ画面で選べる。
- 休息を選ぶと進行中フローを閉じる。失敗、未達、連続記録の中断とは表示しない。
- 時間変更を選ぶと詳細とローカル通知設定を開く。通知同意は従来どおり利用直前に取得する。
- 相談目安はヘルプを開くだけで、外部送信、予約、紹介、診断判定を行わない。

## 4. 支援境界

- 眠気、疲れ、身体の重さへ立つ・歩く・覚醒を上げる行動を自動追加しない。
- 頭の霧には複雑な計画や複数候補を前面表示しない。
- freezeには本人が「先に1つ置きたい」と選んだ場合だけ呼気と視線の準備を置く。
- 混合・不明には複合リチュアルを作らず、原因を1つに決めない。
- 強い状態が続く、生活に影響する、急に強くなった場合は、病名を示さず医療機関へ相談できると案内する。
- 服薬の開始・中止・増減・時刻変更は助言せず、処方した医師または薬剤師への相談を案内する。

## 5. 時刻とデータ契約

新しい状態を選んで計画を作った時点で、次を`InterventionPlan.stateOverlay.localTimeContext`へ保存する。

- UTCの観察時刻
- その端末上の現地日付、時、分
- 取得可能な場合のIANAタイムゾーン
- UTCより東を正とするオフセット分（東京は`+540`）

履歴表示時に現在の端末タイムゾーンから再計算しない。旧記録に欠ける値は補完しない。新しい再試行で状態を選んだ場合は新しい観察時刻を使う。

状態詳細と時刻は計画JSONの一部としてSQLiteへ保存され、本人が任意同期を有効にした場合は計画とともに同期・本人エクスポートの対象になる。AI入力、通知本文、分析イベント、クラッシュログへは加えない。`DailyState`の同期列は変更しない。

## 6. セラピスト利用

使用できる問いは「今いちばん近いのはどれですか。分からない、今は特にないでも大丈夫です」の1問と、freeze時に既存の準備希望を確認する1問までとする。

表示を鑑別診断や治療選択に使わない。長く続く、生活への影響、急な変化等を専門職として把握した場合は、アプリの点数ではなく資格範囲と所属機関の手順に従う。

## 7. 既知の限界

- 状態語の理解しやすさと選択肢の順序は当事者・セラピスト評価が未実施。
- 単一選択のため、複数状態の構成や優先順位は記録できない。
- 時刻は文脈メタデータであり、良い時間帯、概日位相、睡眠負債、服薬効果を推定しない。
- 医療相談の適切な閾値をアプリが判定する機能はない。
- Maestroシナリオは追加するが、実機での通知・タイムゾーン変更確認は未実施。
