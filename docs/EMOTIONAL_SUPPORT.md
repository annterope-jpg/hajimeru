# 気持ちの体験に合わせる支援仕様

版：v0.1

更新日：2026-09-10

対象：Phase 11

## 1. 目的

高い嫌悪を一括して「やる気がない」「不安が強い」と扱わず、本人が選んだ近い体験に合わせて開始前の支援を変える。これは診断、原因推定、感情の治療ではない。質問は既存の短い確認の中に収め、追加インタビューは最大2問とする。

## 2. 確認すること

1. 嫌さに近い体験を複数選ぶ（任意）
2. 脅威・評価・圧力・freezeに近い場合だけ、負担を下げる準備を先に置きたいかを選ぶ（任意）

回答がない場合は推測しない。「まだ分からない」「今は下げずに一歩を試す」では、負担を下げる準備を自動追加しない。

| 本人が選んだ体験 | 本人が希望したときの支援 | 避ける解釈・働きかけ |
|---|---|---|
| 分からなさ・見通しの不安 | 不確かなことを1つ外に出し、確認可能な一歩にする | 全体計画の完成を求める |
| 失敗・評価への怖さ | 非公開の下書き、仮置きとして始める | 完成度や勇気を評価する |
| 恥・自責 | 遅れの取り戻しや説明を開始条件にしない | 反省や埋め合わせを促す |
| 急かされる・反発 | 本人が決めた30秒の範囲へ戻す | 締切、焦り、危機感を一般的な動機として足す |
| 面倒・退屈 | 1分、目に見える変化1つへ短くする | 性格や意欲の不足とみなす |
| 不安・緊張で固まる | 希望時だけ、呼気と視線の短い準備を置く | 低覚醒と決めつけて覚醒を上げる |

複数選択時は、本人が選んだ順で最初に適用可能な支援を1つだけ表示する。情報量を増やさないための試作上の制限であり、最も重要な原因を判定したという意味ではない。

## 3. 開始プランへの反映

- 気持ちの支援は主要ボトルネックの採点を変えない。
- 最初の行動、タイマー、開始キューとは別の任意の準備として表示する。
- 嫌悪が高くても、感情を消すことを開始条件にしない。
- 退屈には短さと可視変化を使う。緊急性、締切直前、罪悪感を動機づけに使わない。
- freezeの鎮静準備は、本人が「先に1つ置きたい」と選んだ場合だけ表示する。

## 4. セラピストとの共同利用

セラピストは「本当の原因」を当てず、画面の候補を本人の言葉を探す足場にする。使える問いは次の2つまでとする。

- 「この嫌さに一番近いものはありますか。複数でも、該当なしでも大丈夫です」
- 「動く前に負担を少し下げる準備を置きたいですか。それとも今のまま一歩を試しますか」

本人の選択と違う支援を勧めるときは、理由を説明し、拒否・保留・終了を残す。急かす、恥を利用する、支援者の安心のために詳細を聞き続けることは禁止する。

## 5. データ境界

感情反応と準備希望は、再開可能にするため進行中フローのローカル下書きにだけ一時保存する。通常の`TaskAttempt`、AI入力、ログ、分析イベント、エクスポートには含めない。開始プランに採用された支援文だけはローカル記録に残り、本人が任意同期を有効にした場合は計画の一部として同期対象になる。

## 6. 既知の限界

- 用語の重なりと本人にとっての分かりやすさは、当事者・セラピストとの評価が未実施。
- 複数の体験を同時に扱う順序の共同調整は未実装。
- fatigue、低覚醒、freeze、概日リズム、認知的離脱に近い状態の追加区別はPhase 12で扱う。
- 効果や因果関係を検証した機能ではなく、安全なUX仮説である。
