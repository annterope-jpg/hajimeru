# 本人主導の共有要約とふりかえり

## 目的

Phase 18は、本人が面談へ持ち込みたい情報だけを選び、編集し、正確なプレビューを見てからOS共有画面へ渡す機能である。セラピスト用ダッシュボード、遠隔監視、診療録連携、自動送信は作らない。共有しないことは常に同等の選択肢であり、開始支援の利用条件にしない。

## 利用者体験

「残しておきたいこと」の各履歴から本人が明示的に編集画面を開く。全項目は未選択から始まり、次の許可リストだけを個別に含められる。

- 本人が編集した課題の短い呼び名
- 今回の作業仮説（確定原因ではない）
- 最初の1動作と時間
- 戻る目印
- 本人が新たに書いた「合った点」「負担だった点」「次に1つ変える点」

タスク本文、評価スコア、デイリー状態、全ロードマップ、価値アンカー、感情の自由記述、EFT、社会支援選択、Phase 17の一時支援、開始率・頻度、試行ID、AI由来情報は自動で含めない。候補文字列も本人が編集・空欄化できる。空欄または未選択の項目はプレビューと共有本文の両方から除く。

## プレビューと共有

編集や選択を変えるたびに以前のプレビューを無効化する。本人が再度プレビューし、「この文章だけを共有画面へ渡します」を確認した後のボタンだけがOS共有画面を開く。アプリは受領者、送信結果、キャンセル、既読、保存、診療録転記を記録しない。「共有画面を開いた」を「共有済み」と表示しない。

確認の目安は1日、7日、表示なしから本人が選べる。これは相手側のコピーを技術的に失効させる期限ではない。共有後のコピーを本アプリから回収・削除できないことを共有前に表示する。

## データ境界

編集下書き、選択、プレビューは画面メモリだけに置く。SQLite、`TaskAttempt`、シェル保存、同期、AI、通知、一般JSON/CSV書き出し、分析、共有履歴へ追加しない。履歴のIDだけを画面遷移パラメータに使い、タスク本文や要約本文をURLへ入れない。編集画面を開いても進行中の開始実験を復元・終了・再試行しない。

## セラピスト利用

受け取ったメモは診断、原因、治療効果、治療遵守の証拠ではない。「本人が今回持ち込みたい項目」として読み、合った点・負担だった点・次の1変更を共同で確認する。受領後の保存先、診療録転記、保持、削除は共有前に説明し、所属機関の規程に従う。

## 既知の限界

- OS共有画面の先で実際に送られたか、誰が受け取ったかは確認しない。
- 相手側に渡ったコピーの撤回・失効・削除を保証できない。
- 下書き保存や複数記録の比較、専門職コメントは実装しない。
- 実機の共有先ごとの表示、文字拡大、スクリーンリーダー読み順は追加評価が必要である。
