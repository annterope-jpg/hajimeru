# 「困った」後の再着手ループ仕様

更新日：2026-09-10
対象：UX確認用試作

## 目的

タイマー後の「困った・止まった」を、失敗判定や原因診断ではなく、次の一歩を調整するための本人の手がかりとして扱う。再試行を既定にせず、時間変更、休息、終了、理由を答えない選択を同じ画面に残す。

## 本人向けフロー

1. ふりかえりで本人が「困った・止まった」を選ぶ
2. 「できなかった理由」ではなく「今の一歩で変えるならどこか」を1つ選ぶ
3. 調整案を確認し、再開、時間・合図の変更、休息、終了から選ぶ
4. 再開する場合は元の試行を`stuck`として閉じ、調整した計画で新しい試行を作る

| 本人が選ぶ手がかり | アプリ内の調整 | 残す選択 |
|---|---|---|
| まだ大きかった | 元の動作の対象を1つ指で示すところまで小さくする | 再開、時間変更、終了 |
| 決めることが残った | 候補を1つ外に出し、判断をあとへ移す | 再開、時間変更、終了 |
| 不安・緊張で固まった | 呼吸と視線の短い準備を加える | 再開、時間変更、休息、終了 |
| 眠さ・頭の霧が強かった | 水、姿勢変更等の準備を加える | 再開、時間変更、休息 |
| 今は選ばない | 調整案を作らない | 終了 |

理由を選ばず終了することもできる。表示は仮説であり、ADHD、気分、不安、睡眠、概日リズム、認知的離脱等の原因や診断を確定しない。

## 記録とプライバシー

- 元の試行には終了時刻と`stuck`だけを保存する
- 再開時は元の記録を上書きせず、新しい試行IDを作る
- 選んだ「困った」の理由はPhase 10では保存、同期、エクスポート、ログ送信しない
- 調整案は端末内のルールだけで作り、AIや外部通信を使わない
- 伴走モード中も、支援者への自動送信や本人回答の上書きは行わない

## セラピストの応答例

- 「できなかった理由を決めるのではなく、今の一歩のどこを変えるか見ます」
- 「一段小さくする、決めることを減らす、時間を変える、休む、ここで終える、どれも選べます」
- 「今は選ばなくても大丈夫です」

避ける表現：

- 「なぜできなかったのですか」
- 「次は必ずできます」
- 「本当の原因はこれです」
- 「せっかく始めたので続けましょう」
- 「休むと癖になります」

安全上の懸念、服薬判断、診断相談が出た場合はこのループを中止し、`SAFETY_BOUNDARIES.md`の手順を優先する。

## 受入基準

- 「困った」から5つの手がかりと理由を答えない終了へ到達できる
- 再試行を強制せず、休息・時間変更・終了を選べる
- 元の試行を上書きせず、調整後は新しい試行として始められる
- 調整後の開始プランを再生成で失わない
- 診断、原因、失敗、改善を断定する表示を使わない

## 既知の限界

- 手がかりは1つだけ選ぶため、複数要因の同時調整はできない
- 一段小さい行動は汎用テンプレートで、本人の環境に合わない場合がある
- 選択理由を保存しないため、後から傾向分析やセラピストとの自動共有はできない
- 過去の記録からこの再着手画面を再度開く導線はない
