# セラピスト用マニュアル v0.6

> Phase 13の声かけ：「イヤさとは別に、始める前の『決める・そろえる』が重い感じはありますか」。近い選択が本人にある場合だけ1つ選び、提案は1件にする。「今は決めない」「ここで終わる」も有効な選択として扱う。

> Phase 14の声かけ：「全部を決めず、今日の範囲・一区切り・保留・次に戻る目印のうち、今分かるものだけ置きますか」。空欄を埋めず、完成後も本人が少し直すか変更せず戻るかを選ぶ。

確認日：2026-09-11
用途：本人端末上での5〜10分の模擬共同利用  
重要：UX確認用の未検証試作であり、診療手順や臨床判断を置き換えない

## 1. 1ページ導入ガイド

### 目的

本人が「やる気がない」と採点されずに、今の着手コストを上げている条件を短く整理し、30秒以内の一歩または仮のロードマップを選ぶための補助具である。同じ止まり方でも、判断の多さ、不快感、低覚醒、弱いキュー、競合行動など、異なる仮説がありうる。

### 最初に守る4点

1. 本人が使いたいかを確認する。使わない、途中でやめる、休む選択を先に伝える
2. 本人が端末を持ち、答えと共有範囲を選ぶ
3. アプリの仮説を診断や正解として説明しない
4. 同じ画面を見ることと、AI・通知・同期・共有の同意を混ぜない

現在の試作は支援者への自動共有を行わない。画面や記録を見せるかは、その都度本人が選ぶ。

### 30秒の導入スクリプト

> このアプリは、やる気や能力を採点するものではありません。同じ「始められない」でも、最初の動きが曖昧、不安が強い、身体が重いなどで支え方が変わります。今日は原因や正解を決めず、今の場面に合いそうな小さな実験を一つ作ります。使わない、途中でやめる、休む、記録を見せないことも選べます。一緒に画面を見てもよいですか。

「はい」を得るだけで終えず、扱う課題と見せたくない内容を確認する。理解テストはせず、「気になる点や、言い換えてほしいところはありますか」と尋ねる。

## 2. 導入前チェック

- [ ] 本人は今日このアプリを使いたい
- [ ] 単独／一緒に見る、どちらを選ぶか確認した
- [ ] 今日扱う課題と、扱わない内容を確認した
- [ ] いつでも閉じる・休む・見せない選択を伝えた
- [ ] 通知や数値が監視感・圧力にならないか確認した
- [ ] 読字、視覚、聴覚、運動、言語化、端末操作の配慮を確認した
- [ ] 現在の主訴が着手支援の範囲内で、安全上の対応を先行すべき状態でないことを専門職として確認した

本人が迷う、沈黙する、同意を撤回する場合は進めない。家族や支援者が利用を希望していても、本人の同意の代わりにしない。

## 3. 10分共同利用台本

| 時間 | 操作 | セラピストの言葉 |
|---:|---|---|
| 0:00–1:00 | 共同利用の確認 | 導入スクリプトを伝え、本人の許可と今日の範囲を確認する |
| 1:00–2:00 | ホームで1課題を入力 | 「今日、少しだけ入口を作りたいことはどれですか」。具体化を急がない |
| 2:00–4:00 | 3問の短い確認 | 一度に1問。本人が迷えばスキップや近い選択肢を認める |
| 4:00–6:00 | 必要時だけ詳細／ロードマップ | 「もう少し確認すると一歩が変わりそうですか」。情報収集を目的化しない |
| 6:00–7:30 | 仮説カードを照合 | 「この仮説は近い、違う、まだ分からないのどれでしょう」 |
| 7:30–9:00 | 最初の一歩と1・3・5分を選ぶ | 「この大きさなら試せそうですか。さらに小さくしても、今日は見送っても大丈夫です」 |
| 9:00–10:00 | 試す／終了を本人が決める | 開始後は完了を求めない。終了時に共有・記録を続けるか再確認する |

時間は目安であり、10分以内の完遂を本人の課題にしない。時間切れなら「次に戻る位置」を1つ残して終了できる。

## 4. 仮説―質問―介入対応表

| 作業仮説 | 追加するなら1問 | 提案の方向 | 避けること |
|---|---|---|---|
| 最初の行動が曖昧 | 「最初に手や足がすることは見えますか」 | 観察可能な30秒動作 | 詳細な計画表を先に完成 |
| 嫌悪・面倒さ | 「どんな嫌さが近いですか。言葉にしにくくても構いません」 | 嫌さを残した最小接近 | 励ましで感情を否定 |
| 不安・freeze | 「分からなさを1つ減らす／緊張を少し下げる、どちらが近いですか」 | 情報1点または緊張低減 | urgencyや恐怖を増幅 |
| 開始直後の変化が見えない | 「1〜3分後に何が見えたら、少し進んだと分かりますか」 | 即時の可視的変化 | 悪い未来を想像させる |
| 判断・努力コスト | 「判断、準備、手順のどこが重そうですか」 | 既定値、保留、1決定削減 | すべて本人に選ばせ続ける |
| 低覚醒 | 「身体を少し起こす／時間を変える／休む、どれが近いですか」 | 短い身体準備か時間変更・休息 | 複雑な認知課題を先行 |
| キューが弱い | 「脱線した後、何が見えたら戻れますか」 | 外部キュー、戻る目印 | 通知を増やし続ける |
| 競合行動 | 「代わりに移りやすい行動との間に、どんな一手間なら置けますか」 | 競合側の小さな摩擦 | スマホ利用を道徳化 |
| 時間が曖昧 | 「どんな出来事の直後なら分かりますか」 | イベントベースの合図 | 厳密時刻を強制 |

高得点でも原因が特定されたわけではない。1回の面接で全仮説を確認せず、画面に出た最大2つと別枠の状態から、本人が話したいものだけを扱う。

## 5. 仮説への返し方

Phase 11では、嫌悪を一括して扱わない。分からなさ、評価への怖さ、恥・自責、圧力、退屈、freezeのうち本人に近い語を確認し、負担を下げる準備を先に置くかは本人が選ぶ。問いは「どれが近いか」「準備を先に置きたいか」の2つまでとし、緊急性、締切、罪悪感を動機づけに使わない。詳しい対応例は`docs/EMOTIONAL_SUPPORT.md`を参照する。

推奨する言葉：

- 「回答した範囲では、今はこの仮説が出ています。近いですか、違いますか、まだ分かりませんか」
- 「違うと分かったことも、次に案を直す情報です」
- 「決めずに短く試すことも、今日は閉じることもできます」

避ける言葉：

- 「あなたの本当の原因はこれです」
- 「ADHDだからこうなります」
- 「この通りにすればできます」
- 「せっかく計画したのでやりましょう」
- 「近いを選べないのは病識がないからです」

## 6. 大きな課題の扱い

状態の確認では「今いちばん近いのはどれですか。分からない、今は特にないでも大丈夫です」と尋ねる。眠気、疲れ、頭の霧、身体の重さ、freezeを鑑別診断に使わず、本人が休息、時間変更、小さい一歩、相談目安のどれを選ぶか確認する。長く続く、生活への影響、急な変化がある場合はアプリの点数で判断せず、資格範囲と所属機関の手順を優先する。詳細は`docs/STATE_CONTEXT_SUPPORT.md`を参照する。

ロードマップは完成手順でなく仮の地図である。本人が迷いを最大3つ選び、今の入口、今日の一区切り、今日の範囲、保留、再開地点を確認する。セラピストが正しい順序を決めず、「今いる場所と次の方向が、本人の感覚と合うか」を優先する。地図作りが新たな回避や疲労になれば、入口または次の再開点だけ残して終える。

## 7. 「困った」後の応答カード

現行アプリでは「困った・止まった」の後に次のカードと同じ5つの手がかりが表示される。本人に画面を渡し、答えを誘導せず、理由を選ばない終了も同じ選択として扱う。

> できなかった理由を決めるのではなく、今の一歩のどこを1つ変えるか見ます。近いものはありますか。  
> ［まだ大きい］［決めることが残った］［不安・緊張で固まった］［眠さ・頭の霧が強い］［今は選ばない］

| 本人の返答 | 応答例 |
|---|---|
| まだ大きい | 「身体動作をもう一段だけ小さくするか、今日は止められます」 |
| 決めることが残った | 「残った判断を1つだけ選ぶか、保留箱へ移せます」 |
| 不安・緊張 | 「急がせず、分からなさを1つ減らすか、緊張を下げて終えられます」 |
| 眠さ・頭の霧 | 「身体準備、時間変更、休息から選べます」 |
| 今は選ばない | 「ここで終えて大丈夫です。説明を求めません」 |

再試行を既定にしない。「なぜできなかった」「次は必ず」と追及しない。

## 8. 記録の読み方

本人が見せたい場合だけ同じ画面を見る。試した一歩と残した一歩を宿題提出として数えない。記録のない日、ふりかえりのない試行、アプリを使わなかった期間を失敗・抵抗・治療意欲の低さと解釈しない。条件の並びは相関として扱い、1回や少数の記録から有効性や原因を断定しない。

## 9. 安全・プライバシー

- 安全上の懸念が出たらアプリを閉じ、所属機関の手順と専門職責務を優先する
- アプリの安全ゲートをリスク評価や安全確認に使わない
- 診断、治療、服薬変更、危機カウンセリングをアプリに委ねない
- 同じ画面を見ることを、同期・AI・通知・データ共有の同意とみなさない
- 本人の画面を撮影・転送・診療録へ転載する場合は、所属機関の規程と別の説明・同意に従う
- タスク文や機微な自由記述を公開Issue、チャット、通常ログへ貼らない

緊急性や安全を専門職として判断する必要がある場合、本マニュアルより資格範囲、法令、所属機関の手順を優先する。

## 10. スーパービジョンと逸脱防止

模擬利用後、次を確認する。

- [ ] 本人より支援者が長く話していなかったか
- [ ] 仮説を本人へ押しつけなかったか
- [ ] 「違う」「分からない」「見送る」を有効な返答として扱ったか
- [ ] 質問を増やして情報収集自体を目的にしなかったか
- [ ] 小さくすることと回避の固定化を、アプリだけで決めつけなかったか
- [ ] exposure的接近と不安低減を混同しなかったか
- [ ] 低覚醒を自責、抵抗、意欲不足として読まなかったか
- [ ] 記録や通知を監視・圧力・治療遵守の採点に使わなかったか
- [ ] 安全上の懸念をアプリの判定に委ねなかったか
- [ ] 本人が終了時に、今後見せる内容を選べたか

逸脱、圧力、羞恥、誤提案、同意の混同、安全上の問題があった場合は試用を止め、所属機関の責任者またはスーパーバイザーへ報告する。個人を特定できる内容を公開リポジトリへ記載しない。

## 試作評価用の短い記録

本人の臨床情報ではなく、模擬利用の手順評価として、本人の別途同意がある場合だけ次を集計する：説明の分かりやすさ、圧力の有無、本人が選択できた感覚、所要時間、操作上の障壁、マニュアル逸脱。タスク本文、診断名、自由記述、危機内容を開発用ログへ含めない。
