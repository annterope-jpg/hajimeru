# Phase 17 — 脱線・再開・切替の最小支援

## 目的
着手に隣接する「別の活動から切り替えにくい」「いったん離れると戻りにくい」に対して、一般的な生産性管理へ広げず、最小の橋だけを開始プランへ置く。

## 臨床仮説と境界
- `competingReward` が本人回答から主要仮説に選ばれた場合、好きな活動を禁止・没収せず、10秒だけ中断して次の対象へ手を移す橋を置く。
- `cueWeakness` が本人回答から主要仮説に選ばれた場合、離れる前に再開位置を1つだけ外部化する。
- タスク自体が `transition` と明示的に分類された場合は、切替橋を置ける。
- 上記がない場合は支援を推測して追加しない。

これは原因診断、ADHD特性判定、依存評価、治療効果の主張ではない。アプリ使用時間、他アプリ利用、達成率、連続日数は監視しない。

## 利用者向け表示
既存の開始プラン欄を使い、切替が必要な場合は「今していることを10秒だけ止め、次に使う物か画面へ手を移す。続けるかは、その後に決める」と表示する。再開支援では「離れる前に、戻る場所を1つだけ見える形で残す」と表示する。

好きな活動を悪い行動と扱わず、完全にやめることを開始条件にしない。合わない場合は通常どおり本人がプランを使わず開始・見送り・休息を選べる。

## セラピスト向け
切替橋は遵守課題にせず、「今の条件で一番小さい切替は何か」を本人と照合する材料にする。再開目印も宿題チェックや監視には使わない。本人がゲーム、動画、SNS等を選んでいても、それ自体を病理・依存・回避と断定しない。

## データ境界
新しい自由記述、監視、アプリ利用履歴、外部送信は追加しない。Phase 17は既存の `InterventionPlan.distractionFriction` と `InterventionPlan.returnCue` に、回答済み仮説または明示的なtransitionカテゴリから決定的な固定文を入れるだけとする。AI入力、通知本文、同期スキーマ、分析イベントは変更しない。

## 既知の限界
- `competingReward` と `cueWeakness` の既存質問が実際の切替・脱線体験を十分に表すかは当事者評価が必要。
- 10秒という長さは設計仮説であり、有効性を示すRCT根拠として扱わない。
- スマホ以外の環境、複数の競合活動、頻繁なタスク切替を管理する一般的な生産性機能には拡張していない。
