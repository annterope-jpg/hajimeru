# Phase 19：当事者・セラピスト共同パイロット実施プロトコル

更新日：2026-09-15
状態：実施準備完了・人間参加の実施待ち

## 目的

Phase 19では、新しい治療効果を示すことではなく、現在の試作「はじめの地図」を本人端末上で当事者とセラピストが一緒に使ったときに、本人の自己決定、理解しやすさ、心理的圧力、共有境界、安全境界、操作負担が設計どおり保たれるかを確認する。

このパイロットは有効性試験、診断、治療評価、服薬評価ではない。開始率、完了率、連続利用、症状改善を主要成果にしない。

## 実施前の必須条件

外部の患者・利用者を参加させる前に、次をすべて満たす。

1. 実施責任者と、臨床安全上の問題・苦情を受ける非公開連絡経路を決める。
2. 所属機関で必要な倫理、法務、個人情報、研究・品質改善の手続きを確認する。
3. 参加は任意で、断っても診療・支援上の不利益がないと説明する。
4. アプリは診断、治療選択、服薬判断、危機評価を行わないと説明する。
5. 同じ画面を見ること、共有メモを作ること、OS共有を使うこと、診療録へ転記することを別々の行為として扱う。
6. 実症例・患者情報・自由記述を公開GitHub、Issue、PR、開発ログへ記録しない。

これらを満たさない場合、外部参加者での実施は開始しない。

## 対象と規模

最初は小規模の形成的UXパイロットとする。人数を事前に固定して統計的有効性を主張する設計にはしない。異なる利用者像と複数のセラピストで、同じ問題が繰り返されるかを確認する。

参加者は原則18歳以上で、本人が試作評価への参加と同席利用に同意できることを前提とする。急性の安全上の懸念、判断能力に関する懸念、研究・評価参加より臨床対応を優先すべき状況では実施しない。

## 1回のセッション

### 1. 導入

- 本人が端末を持ち、本人が操作する。
- 今日一緒に見る範囲と終了目安を本人が選ぶ。
- いつでも中止、休息、単独利用、非共有へ戻れることを確認する。
- セラピストは正解を教える役ではなく、本人の言葉とアプリの仮説のずれを確認する役とする。

### 2. 共同利用

通常のアプリ導線を変更せず、少なくとも以下を観察する。

- 質問の意図が本人に伝わるか。
- 仮説へ「近い・違う・まだ分からない」と返しやすいか。
- 30秒の一歩、時間変更、休息、見送りが同等の選択肢として感じられるか。
- 感情、低覚醒、判断負担、大きな課題、EFT、社会的支援、再開支援が過剰な聞き取りにならないか。
- セラピスト同席が監視、宿題確認、達成評価に変わっていないか。

### 3. 共有要約

共有要約を試す場合も任意とし、何も選ばない状態から始める。本人が選んだ項目だけを確認し、共有しないことを不参加・抵抗と解釈しない。OS共有へ進んだ後の受領、保存、二次利用はアプリが保証しない。

### 4. 終了

本人が終了を選び、利用継続を求めない。未完了、見送り、休息、仮説の不一致も有用な観察として扱う。

## 評価項目

数値は成績化ではなく、問題箇所を見つける補助に限る。個人別の開始率・完了率・利用回数を評価しない。

### 本人から確認すること

- 何を聞かれているか分かりにくかった箇所
- 圧力、恥、自責、監視されている感じが生じた箇所
- 選択肢が足りない、または多すぎた箇所
- 「近い・違う・まだ分からない」を言いやすかったか
- 中止、休息、見送り、非共有を選びやすかったか
- 共有範囲を自分で決められた感覚があったか
- 次回変えるなら1点だけ何を変えるか

### セラピストから確認すること

- 診断・原因・治療効果を推定したくなる表示がなかったか
- 本人の回答を誘導・上書きしたくなる箇所がなかったか
- 宿題確認や遵守評価へ流れやすい設計がなかったか
- 安全上の懸念がある場面でアプリを止められる構造だったか
- 同意、共有、診療録転記の境界が実務上理解可能だったか
- 共同利用を5〜10分程度の短い検討として運用できるか

## 停止基準

次のいずれかが起きた場合、その場の通常アプリ評価を中止し、必要なら所属機関の手順を優先する。

- 危機、安全上の懸念、急性の臨床対応が必要になった。
- 本人が中止、休息、非共有を希望した。
- 本人が参加を断りにくい、評価されている、監視されていると感じている。
- アプリ表示が診断、治療、服薬判断として受け取られた。
- 個人情報や機微情報が意図しない送信・共有・ログへ入る疑いが出た。
- セラピストが本人の回答を上書き、強制、採点する運用になった。

同じ設計上の問題が複数回再現する、または1回でも安全・プライバシー上重大な問題が出た場合は、新規参加を止め、修正と再レビューを先に行う。

## データ最小化

パイロット記録は、必要最小限の匿名化された設計フィードバックに限定する。氏名、連絡先、診断名、具体的な課題本文、実症例の経過、自由記述の原文を開発リポジトリへ入れない。

推奨する開発側の記録単位は「画面/機能」「問題種別」「再現条件」「重大度」「修正候補」「再確認済みか」であり、個人の成績表を作らない。

## Phase 19を完了とみなす条件

次をすべて満たしたときだけPhase 19を「完了」とする。

1. 実際の当事者とセラピストによる共同利用が少なくとも1回以上行われている。
2. 本人の中止・休息・見送り・非共有の選択が実地で確認されている。
3. 理解しにくさ、心理的圧力、共有境界、安全境界について記録された所見がある。
4. 重大な問題があれば修正し、必要部分を再確認している。
5. 結果を効果・有効性として過大解釈せず、Phase 20の統合監査へ渡せる。

AIだけの模擬評価、単体テスト、CI通過のみではPhase 19完了とはしない。

## 現在の状態

2026-09-15時点では、プロトコル、同意確認事項、評価項目、停止基準、記録様式を固定した「実施準備完了」の段階である。実際の当事者・セラピスト共同パイロットは人間参加を必要とするため、自動改修では実施済みと記録しない。
