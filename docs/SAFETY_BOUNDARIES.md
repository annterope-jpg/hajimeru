# はじめの地図：倫理・安全・法務の境界仕様

版：0.1  
確認日：2026-09-04  
状態：UX確認用試作のPhase 2仕様

## 1. 目的

本書は、通常の着手支援を続けてよい範囲と、通常フローを止めて別の案内・専門職判断へ移る範囲を定める。安全ゲートは診断、危機評価、治療判断ではなく、任意AIへ送信してはいけない入力を保守的に振り分ける仕組みである。

本書は医療・法律上の助言ではない。正式公開、医療機関での利用、セラピスト伴走機能の提供前に、臨床、安全、法務、プライバシーの専門家確認を受ける。

## 2. 共通原則

- アプリの目的は日常の着手困難に対するセルフマネジメント補助である
- 診断、治療、心理療法、服薬判断、臨床的リスク評価を行わない
- 危機、服薬変更、診断要求、個人情報の可能性がある入力は通常AI提案へ送らない
- パターンに一致しなかったことを「安全」と医学的に判定したとはみなさない
- 通常提案を止めても、入力文、該当語、ユーザーIDをログや通知へ再掲しない
- 本人がアプリを閉じる、入力を削除する、共有しないことを選べる
- セラピスト同席時は、アプリより専門職の責務と所属機関の手順を優先する
- アプリは常時監視されておらず、緊急対応サービスではない

## 3. 通常フローを止める境界

| 入力・状況 | アプリの動作 | 利用者への案内 | 行わないこと |
|---|---|---|---|
| 自傷・自殺・他害を示す可能性のある表現 | AI送信と通常の着手提案を停止 | 差し迫る危険は119、警察が必要なら110、最新の公的相談先 | リスクの程度の判定、質問による危機評価、会話型介入 |
| 薬の開始・中止・増減・用量変更 | AI送信と通常提案を停止 | 処方した医師または薬剤師へ相談 | 薬剤選択、服用時刻・量の変更、断薬・休薬の提案 |
| ADHD等の診断・判定・重症度要求 | AI送信と通常提案を停止 | 訓練を受けた専門家による評価を案内 | 疾患名、可能性、重症度、スコア判定 |
| 構造化された連絡先・住所・個人番号等 | AI送信を停止 | 個人を特定できる部分を削除して再入力 | 入力文のエコー、ログ保存、部分マスキングだけでの送信 |
| AIが`riskFlag`を返す、出力形式が不正 | AI案を破棄 | 医学的内容を含まない安全なローカル案または終了 | AI本文の一部利用、エラー本文への入力転載 |
| 面接中にセラピストが安全上の懸念を認める | アプリ利用を中断 | 所属機関の安全手順へ移る | アプリ結果を臨床判断の根拠として単独使用 |

複数分類が同時に該当する場合は、危機案内を最優先する。ただし、他の該当分類を外部へ送ったり、入力本文を記録したりしない。

## 4. 現行安全ゲートの能力と限界

### 実装済み

- 端末内で危機、服薬変更、診断要求、構造化PIIをパターン照合する
- 危機を最優先し、AI送信を不許可にする
- 安全分類の戻り値に入力本文や一致語を含めない
- Edge Function側にも同等の事前検査を置く
- AIの構造化出力、件数、長さ、許可タグを検証する
- タイムアウト、拒否、不正出力ではローカル案へ戻る

### 限界

- 見逃しと誤検出の両方がありうる
- 婉曲表現、文脈、否定、引用、第三者についての記述を完全には理解できない
- 自由文に含まれる機微情報をPII正規表現だけでは除去できない
- 急な身体症状、事故、暴力、虐待、酩酊、運転・火気・高所等の危険状況を網羅的に分類しない
- ローカル提案も本人の身体状態、環境、実行可能性を保証しない
- 安全ゲートを通過したことは、医学的または物理的安全の保証ではない

この限界は利用者向け説明とセラピスト用マニュアルにも反映する。分類範囲を広げる場合は、誤検出による不利益、相談先、テストケースを同じ変更で追加する。

## 5. 危機時案内の境界

### アプリが行うこと

- 通常のタスク提案を停止する
- 差し迫る危険では119、警察が必要な場合は110を案内する
- 厚生労働省「まもろうよ こころ」へのリンクを表示する
- 代表的な相談先を表示する場合は、出典と確認日を管理する

### アプリが行わないこと

- 自殺・他害リスクの段階評価
- 安全計画の自動生成
- 本人への自動架電、位置情報送信、第三者・セラピストへの自動通報
- 「大丈夫です」等の安全保証
- チャットによる危機カウンセリング

### 相談先の確認

- #いのちSOS：0120-061-338、毎日24時間
- よりそいホットライン：0120-279-338、24時間。050で始まるIP電話は050-3655-0279
- こころの健康相談統一ダイヤル：0570-064-556。曜日・時間は都道府県等で異なる

アプリは公的ページへのリンクを主導線とし、固定番号だけに依存しない。

## 6. 相談先情報の更新責任

| 時点 | 確認すること | 記録先 |
|---|---|---|
| 評価参加者の募集前 | URL、番号、受付時間、対象地域 | 本書とリリースチェックリスト |
| 新しい配布版の公開前 | 上記すべて、画面表示、リンク動作 | リリースPR |
| 公開中は少なくとも3か月ごと | 公式ページの変更、終了・追加窓口 | 本書の確認日と変更履歴 |
| 不一致の報告を受けた時 | 直ちに公式情報と照合 | 安全インシデント記録 |

責任者が未指定の間は外部参加者を募集しない。担当者が変わっても更新が止まらないよう、個人名ではなく「臨床安全責任者」という役割に割り当てる。

## 7. 服薬に関する境界

- 処方薬を飲むこと自体を日常タスクとして入力する場合でも、アプリは処方内容の正しさを確認しない
- 現在の処方どおりの単純なリマインダーと、開始・中止・増減・時刻変更の相談を区別する
- 副作用、効き方、飲み忘れ後の対応、他薬との併用は医師または薬剤師へ案内する
- セラピストは、資格範囲を超えて服薬変更を助言しない
- 服薬内容や薬剤名をセラピストへ自動共有しない

服薬リマインダー自体の追加は本ロードマップの初版範囲外であり、臨床・法務確認なしに追加しない。

## 8. 診断・治療に関する境界

- アセスメント7軸、状態記録、利用履歴からADHD、うつ、睡眠障害、CDS等を推定しない
- ボトルネックを症状名、特性、重症度として表示しない
- 「この記録ではこう並んだ」と「この状態が原因である」を区別する
- アプリ単体をCBT、心理教育、リハビリテーション、医療者による治療と呼ばない
- セラピスト伴走時も、アプリは治療計画や診療録を自動生成しない

受診を勧める場合は病名を示唆せず、生活・仕事・学業への困りごとの持続、強い睡眠・気分・身体症状、服薬相談等の観察可能な理由を示す。

## 9. セラピスト伴走時の責任境界

### 本人

- アプリを使うか、何を入力・共有するかを決める
- いつでも共同利用を中断できる
- アプリの提案を選ばず、修正し、休息を選べる

### セラピスト

- アプリの仮説を本人と照合する
- 安全上の懸念があればアプリを中断し、所属機関の手順を優先する
- アプリ出力を診断、治療効果、服薬判断の代替にしない
- 欠測、不使用、未開始を治療意欲や遵守の不足と解釈しない
- 診療録へ転記する場合は内容を自ら確認し、所属機関の規程に従う

### 運営者

- アプリが常時監視・緊急対応されないことを明示する
- 相談先、プライバシー、安全上の既知の限界を更新する
- 誤提案や漏えいの報告経路、調査、配布停止、修正版配布の手順を用意する
- セラピストの資格・所属を確認する機能を作らない段階では、「医療者用機能」と宣伝しない

## 10. 有害事象・誤提案・苦情

### 対象

- 危機、服薬、診断、PIIが通常AIへ送られた
- 危険な状況で通常の着手提案が表示された
- 羞恥、圧力、強制、監視感を生む表示または運用
- 共有同意を超えた閲覧・送信・保存
- 誤った相談先、切れた緊急リンク
- アプリ提案に関連して生じた、または関連が疑われる不利益

### 最小記録

- 受付日時、版、OS、機能、発生した影響、再現可否
- 本文そのものを必要なく収集しない
- 実在する患者のタスク文、診断、連絡先をGitHub Issueへ投稿しない
- 因果関係が不明でも「関連なし」と早期判断せず記録する

### 初動

1. 差し迫る安全問題なら該当機能または配布を停止する
2. 本文をコピーせず、最小限の再現条件を確保する
3. 臨床安全、プライバシー／セキュリティ、技術の担当へ振り分ける
4. 影響範囲と暫定対策を記録する
5. 修正後に回帰テストし、必要なら利用者へ既知の問題を通知する

### 公開前の制約

現在、実在患者の臨床安全報告を受ける非公開窓口と責任者は確定していない。これらが整うまで、GitHub公開コードの閲覧・技術的UX確認を超えて、外部の患者を研究・臨床評価へ募集しない。

## 11. 医療機器プログラム該当性

厚生労働省は、医療機器としての目的性と、意図どおり機能しない場合の生命・健康への影響等を該当性判断の要素として示している。名称や免責だけでなく、機能、対象者、広告、セラピスト用資料、実際の使用方法を一体として確認する。

正式公開または医療機関との評価前に、次を準備して[PMDA SaMD一元的相談窓口](https://www.pmda.go.jp/review-services/f2f-pre/strategies/0011.html)を含む専門家相談を検討する。

- 意図する使用目的と対象者
- 入力、ルール、AI、出力、共有のデータフロー
- 診断・治療を行わない境界と実際の表示
- 誤動作時に想定される健康影響
- セラピスト伴走の実態とマニュアル
- 評価計画、既知の限界、有害事象対応

参考：[厚生労働省「医療機器プログラムについて」](https://www.mhlw.go.jp/stf/seisakunitsuite/bunya/0000179749_00004.html)

## 12. 個人情報と臨床利用

医療機関等が扱う病歴、身体状況、病状、治療、障害の事実等は要配慮個人情報となりうる。取得や第三者提供の同意、目的、保持、委託、削除を一般アプリの同期と分けて設計する。

- セラピスト伴走を理由に自動同期を有効化しない
- 本人が同じ画面を見せることと、サーバー共有への同意を同一視しない
- 診療録への転記は自動化せず、専門職が確認する
- タスク本文、価値アンカー、競合行動、EFT、自責・不安の自由記述を機微情報として扱う
- GitHub Issue、クラッシュログ、分析イベントへ実在患者情報を含めない

参考：[個人情報保護委員会・医療介護関係事業者向けガイダンス](https://www.ppc.go.jp/personalinfo/legal/iryoukaigo_guidance/)

## 13. リリース停止条件

次のいずれかが未解決なら、新しい評価配布または正式公開を行わない。

- 危機・服薬・診断・PIIが通常AIへ送信される既知の不具合
- 相談先の確認日と責任者が不明
- 実在患者の安全・プライバシー報告を非公開で受ける経路がない
- 同意を超えた共有または削除不能
- 医療目的性について専門家確認が必要と判断されたまま未相談
- 重大な有害事象の調査と暫定対策が未完了
- 安全回帰テストが失敗

## 14. 変更管理

安全境界を変更するPRは、通常UI変更から分け、次を含める。

- 変更する境界と理由
- 新たに止める入力、または通す入力
- 誤検出と見逃しの影響
- 利用者・セラピスト向け文言
- ログ、AI、同期、共有への影響
- 正常、複合分類、否定・引用、個人情報を含むテスト
- 公的情報の出典と確認日
- 専門家確認の要否
